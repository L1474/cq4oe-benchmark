评分方法说明

评测方法与指标

新建运行

这里解释分数如何得到、不同统计口径如何区分。评测台只运行仓库内的评分脚本；你的生成方法在外部运行。

一次评测怎么进行

  1. 对齐输入。 Web 根据任务和领域读取仓库中的 CQ 与金标准；上传文件只提供预测结果。
  2. 准备词项对齐。 CQ2Term 对类、属性词项建立一对一映射；CQ2Onto 先对齐本体中的类和属性，下游结构评测复用这份映射。
  3. 评测结构与覆盖。 CQ2Onto 继续检查属性特征、domain/range 三元组、TBox 公理和推理层级，并将结果关联回 CQ。
  4. 保存结果。 结构化指标、TP/FP/FN、阶段日志、原始产物和脚本生成的 report.md 一起归档到本次 run。

共用分数

TP（正确匹配）
预测项与金标准项按本维度规则匹配。
FP（多报）
预测存在，但金标准中没有对应项。
FN（漏报）
金标准要求，但预测没有覆盖。
精确率
TP / (TP + FP)。预测出来的项目有多少是对的；越低通常表示多报较多。
召回率
TP / (TP + FN)。金标准要求的项目覆盖了多少；越低通常表示漏报较多。
F1
精确率与召回率的调和平均。名称相同不代表统计范围相同，必须同时看任务、维度、层级和范围。

网页中的比例分数用 0～1 表示并显示两位小数；原始 JSON、CSV 和数据库保留计算精度。分母为 0 时指标可能为空，不应当作 0 分。

原始报告为什么有时多、有时少

报告模板由 CQ2Term / CQ2Onto 原评测脚本生成，数值和样例取自本次预测。主要评测步骤固定，但误报、漏报、错配、未对齐项等明细会按结果出现或省略；它不是 Web 把一组分数机械填进固定表格。报告正文目前保持脚本原有英文，运行详情额外提供中文指标摘要。

问题：模型能否找出回答每个 CQ 所需的类和属性？评测分两步：先统一词项，再检查词项是否出现在正确的 CQ。

1. 词项匹配与对齐

类和属性分别比较。脚本计算硬匹配、序列匹配、Levenshtein、Jaro-Winkler 和语义相似度。单项方法分数用于诊断候选词是否相似；它们不是最终总分。

最终映射将每个候选词对的 Top-N 方法分数取平均，低于阈值的候选被丢弃，再做一对一匹配。默认 Top-N 为 3，最终阈值为 0.6。这个映射用于判断不同写法是否表达同一金标准词项。

语义相似度表示词项文本/嵌入的接近程度，不等于本体结构正确，也不应单独当作任务得分。

2. 全领域词项 Precision / Recall / F1

把整个领域所有 CQ 的唯一类和属性分别汇总后评分。类别结果可以分开看，也可以看“类与属性合并”的综合结果；记录页摘要展示综合分数。

它不检查词项放在哪一道题下。只要预测词项在领域其他 CQ 出现，仍可能被全领域词项分数计为覆盖。因此它回答的是“词汇集合认得对不对”，不是“逐题理解对不对”。

3. CQ 覆盖率

先用上一步的一对一词项映射，再逐 CQ 检查：映射后的预测词项是否出现在对应 CQ 的预测行中。默认使用 CQ 本地模式，不会把答在别的 CQ 下的词项算作本题覆盖。

逐题覆盖率
本题被覆盖的金标准类/属性数 ÷ 本题金标准类/属性总数。
至少覆盖一个
至少命中一个所需词项的 CQ 占全部 CQ 的比例。
平均覆盖率
先算每个 CQ 的覆盖比例，再对 CQ 取平均。网页摘要显示这一项。
完全覆盖
本题所有金标准类和属性都覆盖的 CQ 占全部 CQ 的比例。

全领域 F1 高、平均 CQ 覆盖低，通常表示词汇基本找对了，但有些词放错了问题，或漏掉了个别问题所需词项。

问题：生成的本体是否包含金标准要求的词项、关系、公理和层级？CQ2Onto 按维度报告，不把这些内容合成一个总分。

1. 类与属性对齐

分别把预测本体中的类、属性和金标准词项配对。每种匹配方法先独立报告相似度；最终对候选配对的 Top-N 方法分数聚合，应用阈值后建立一对一映射。

网页摘要中的类 F1 和属性 F1 是最终综合对齐的 Precision / Recall / F1。后续三元组、公理和层级评测会复用这份映射；如果映射错，错误可能继续影响下游结构分数。

报告里的单方法分数用于检查对齐过程。排查异常时，优先查看 alignment trace 和 best matching 文件。

2. 属性特征

检查已对齐的对象属性是否具有正确的 OWL 特征：Functional、InverseFunctional、Transitive、Symmetric、Asymmetric、Reflexive、Irreflexive。

这些特征逐项当作二元判断：金标准和预测都声明为 TP；金标准有而预测没有为 FN；预测多声明为 FP。Symmetric / Asymmetric、Reflexive / Irreflexive 是互斥语义对，错设会形成一边 FP、一边 FN。

对齐范围只在已匹配属性对上统计；本体级范围还会把带特征但没有匹配到的金标准对象属性计为漏项。两个范围的分母不同，不能只比指标名。

3. domain / range 三元组

提取 rdfs:domain 和 rdfs:range 声明，检查每个属性的定义域、值域及类型。

语义诊断（第 2 层）
嵌入相似度用于观察候选语义接近程度，不是严格结构正确率。
对齐条件（第 3 层）
只评估已对齐属性；domain 用类映射比较，range 按对象/数据属性类型处理。
全局（第 4 层）
把未对齐属性上的声明也纳入总体范围。对齐范围高而全局低，说明结构可能不错，但词项对齐或覆盖存在缺口。
mismatch
双方都声明了值但不一致；评分同时增加一个 FP 和一个 FN。

4. Atomic TBox 与公理评测

Atomic TBox 提取是中间步骤，不是分数。评测器从上传本体提取原子 TBox 公理，供后续对齐和比较使用。报告和产物会保留 JSON / TXT / XLSX 等文件。

语义候选（第 2 层）
嵌入相似度帮助检索候选公理，是诊断信息，不等价于结构匹配。
严格对齐（第 3 层）
复用类/属性映射后比较公理结构。正确为 TP；缺失、多余为 FN / FP；同类公理结构不一致的 mismatch 同时计 FP 和 FN。
全局（第 4 层）
在严格结果上纳入未对齐主题上的公理：未对齐预测公理增加 FP，未对齐金标准公理增加 FN。

公理的全局 F1 低于严格 F1，常见原因是词项没对齐或额外生成了公理；严格 F1 低则表示已对齐词项上的公理结构仍有差异。

5. 层级闭包

使用 HermiT reasoner 计算类和属性的可推出层级关系，再和金标准层级比较。指标包括类层级、属性层级和合并后的层级 Precision / Recall / F1。

闭包会计入显式声明之外、可由推理推出的关系。它衡量的是逻辑推论是否一致，不表示预测文件中显式写出了所有这些关系。

层级 F1 看推理关系整体匹配；闭包 CQ 覆盖看推理能否补足回答每道 CQ 所需的公理关系。

6. CQ 公理覆盖

每道金标准 CQ 都关联一组所需 TBox 公理。脚本计算至少覆盖一个、平均覆盖率和完全覆盖三种结果：

  • 至少一项：至少匹配一条所需公理的 CQ 占比。
  • 平均覆盖：各 CQ 已覆盖公理数 / 该题所需公理数，再对 CQ 取平均。
  • 完全覆盖：所需公理全部覆盖的 CQ 占比。

严格覆盖只算直接匹配公理；闭包覆盖额外检查 HermiT 推出的层级关系。两种覆盖率是不同口径，不能互相替代。
