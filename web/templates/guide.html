新建运行
评测台只运行评分脚本。Agent 和模型在这里仅作为记录标签；生成预测产物时使用你自己的程序、服务或 Agent。了解各项分数的计算方法与含义 →
01

下载对应领域的 CQ 包

到领域目录选择任务和领域，下载 CQ 包。包内的 cqs.json 是要交给外部生成程序的问题；manifest.json 列出必须覆盖的 CQ ID 和包版本。CQ2Term 包还附带 prediction_template.json。

02

在外部运行自己的生成方法

把该领域的全部 CQ 提供给你的方法。生成程序的启动命令由你自己的实现决定；评测台不会调用你标注的生成模型接口，也不要求上传生成代码。评分中的词项对齐仍会使用本地 embedding 服务。

CQ2Term

按每个 CQ 预测类和属性。填写下载包中的模板，保留每个 id，给 class 和 property 填入字符串数组。一个领域最终交一个 UTF-8 JSON 文件。

[
  {"id": "CQ1", "value": "原 CQ 文本", "class": ["Animal"], "property": ["eats"]}
]

CQ2Onto

依据该领域全部 CQ，生成一个最终本体。可以一次生成（normal）、逐 CQ 生成后合并（cqbycq），或由多步骤 Agent 生成（agent）；这三个名称代表生成方法，不代表要上传三份文件。

cqbycq/你的模型/ontology/wine_ontology.owl  ← 上传这一个最终文件
cqbycq/你的模型/log/wine_log.txt            ← 生成日志，可留在本地
03

按任务 / 领域逐项上传

在运行页选择 Agent 和模型标签，添加任务 / 领域。每添加一个条目，就上传该条目的一个预测文件；一次运行可以包含多个条目。

任务上传文件检查规则
CQ2Term一个 .json必须覆盖该领域全部 CQ ID，不得重复；每行都有字符串数组 class 和 property。
CQ2Onto一个 .owl/.rdf/.xml/.ttl/.nt/.n3.owl/.rdf/.xml 使用 RDF/XML；运行前浏览完整 CQ 清单，点一次“已阅，继续”。

上传的是最终预测产物。CQ 包、外部生成日志、生成代码、金标准和 report.md 都不用上传；评测日志、指标和报告由评测台生成。单个上传文件上限为 50 MB。

04

查看结果与对比

提交后到运行记录查看状态。运行详情展示分层指标、阶段日志、report.md 和可下载的原始产物；记录页可以筛选并对比 2～4 次运行。

05

指标怎么读

网页分数按 0～1 显示两位小数，数值越高通常越好；数据库和下载的原始结果保留完整精度。趋势只对任务、领域、金标准、评测器及配置兼容的记录计算。

精确率
预测为正确的项中，真正匹配金标准的比例：TP / (TP + FP)。
召回率
金标准项中，被预测覆盖的比例：TP / (TP + FN)。
F1
精确率和召回率的调和平均。相同名称的 F1 必须结合维度、层级和统计范围阅读。
CQ 覆盖率
逐题查看该 CQ 所需词项或公理被覆盖的比例；“平均”是各 CQ 覆盖率的平均，不等同于全领域词项分数。
AC / 全局
AC 只比较已经对齐的项；全局包含未对齐项。三元组、公理等维度应优先核对统计范围。
严格 / 闭包
严格匹配只计直接匹配的公理；闭包还计入 HermiT 推理得到的层级关系。

CQ2Onto 分别评估类、属性、三元组、公理和层级，没有单一总分。原始 report.md 是仓库内评测脚本生成的英文报告；运行详情另提供基于结构化指标的中文摘要。
