评分方法说明

评测方法与指标

新建运行

这里解释分数如何得到、不同统计口径如何区分。评测台只运行仓库内的评分脚本；你的生成方法在外部运行。

一次评测怎么进行

CQ 是“本体应能回答什么”的能力问题。CQ2Term 的金标准是每题显式提到的类和属性；CQ2Onto 的金标准是按 CQ 保留的本体片段和必要 TBox 公理，还包含回答问题所需的隐式或派生词项。两项任务的金标准对象不同，分数不能混成一个总分。

  1. 对齐输入。 Web 根据任务和领域读取仓库中的 CQ 与金标准；上传文件只提供预测结果。
  2. 准备词项对齐。 CQ2Term 对类、属性词项建立一对一映射；CQ2Onto 先对齐本体中的类和属性，下游结构评测复用这份映射。
  3. 评测结构与覆盖。 CQ2Onto 继续检查属性特征、domain/range 三元组、TBox 公理和推理层级，并将结果关联回 CQ。
  4. 保存结果。 结构化指标、TP/FP/FN、阶段日志、原始产物和脚本生成的 report.md 一起归档到本次 run。

共用分数

TP（正确匹配）
预测项与金标准项按本维度规则匹配。
FP（多报）
预测存在，但金标准中没有对应项。
FN（漏报）
金标准要求，但预测没有覆盖。
精确率
TP / (TP + FP)。预测出来的项目有多少是对的；越低通常表示多报较多。
召回率
TP / (TP + FN)。金标准要求的项目覆盖了多少；越低通常表示漏报较多。
F1
精确率与召回率的调和平均。名称相同不代表统计范围相同，必须同时看任务、维度、层级和范围。

网页中的比例分数用 0～1 表示并显示两位小数；原始 JSON、CSV 和数据库保留计算精度。分母为 0 时指标可能为空，不应当作 0 分。

同一名称，不同问题：“类 F1”检查词汇对齐，“三元组 F1”检查 domain/range，“公理 F1”检查逻辑结构，“层级 F1”检查推理闭包。阅读数值时至少带上任务、维度、层级和统计范围；只比较两个孤立的 F1 数字没有意义。

原始报告为什么有时多、有时少

报告模板由 CQ2Term / CQ2Onto 原评测脚本生成，数值和样例取自本次预测。主要评测步骤固定，但误报、漏报、错配、未对齐项等明细会按结果出现或省略；它不是 Web 把一组分数机械填进固定表格。报告正文目前保持脚本原有英文，运行详情额外提供中文指标摘要。

先看统计范围，再看 Precision、Recall、F1。出现空值（报告中常写作 — 或 N/A）时，先检查该列是否有可比较的项；不要直接把空值理解成零分。网页用两位小数便于扫读，核对边界情况时以下载的原始 JSON/CSV 和报告为准。

问题：模型能否找出回答每个 CQ 所需的类和属性？评测分两步：先统一词项，再检查词项是否出现在正确的 CQ。

1. 词项匹配与对齐

输入是每道 CQ 的预测类/属性列表和该任务的显式词项金标准。脚本先分别收集类与属性的唯一词项，再为金标准词项与预测词项的候选配对计算硬匹配、序列相似度、Levenshtein、Jaro-Winkler 和 embedding 语义相似度。

硬匹配命中直接给候选对 1.0；否则对非硬匹配方法取最高的 N 个分数求平均。低于最终阈值的候选被丢弃，剩余候选按分数贪心选择，且一个金标准词项和一个预测词项最多各参与一次。默认 N=3、CQ2Term 最终阈值=0.6。

原报告的 Step 2 — Per-Method Matching Results 是各方法独立跑出的诊断分数；Step 3 — Best Matching Selection 才是最终映射。查看 class_alignment.csv、property_alignment.csv 和 *_best_matching.csv 可追踪候选为何被接受或拒绝。

相似不等于回答正确：最终映射只解决“两个名字是否可视为同一词项”，是否在正确的 CQ 中出现还要看逐题覆盖。

2. 全领域词项 Precision / Recall / F1

把整个领域所有 CQ 的唯一类和属性分别汇总后评分。类别结果可以分开看，也可以看“类与属性合并”的综合结果；记录页摘要展示综合分数。

它不检查词项放在哪一道题下。只要预测词项在领域其他 CQ 出现，仍可能被全领域词项分数计为覆盖。因此它回答的是“词汇集合认得对不对”，不是“逐题理解对不对”。

金标准词项有被对齐的预测词项算 TP；没有算 FN；预测词项不能反向对应任何金标准词项算 FP。由此计算 Precision、Recall、F1。原报告的 Step 4 — Term-level Metrics 给出仅类、仅属性和合并词项三行，后面还列出漏项与额外词项。

3. CQ 覆盖率

先用上一步的一对一词项映射，再逐 CQ 检查：映射后的预测词项是否出现在对应 CQ 的预测行中。默认使用 CQ 本地模式，不会把答在别的 CQ 下的词项算作本题覆盖。

逐题覆盖率
本题被覆盖的金标准类/属性数 ÷ 本题金标准类/属性总数。
至少覆盖一个
至少命中一个所需词项的 CQ 占全部 CQ 的比例。
平均覆盖率
先算每个 CQ 的覆盖比例，再对 CQ 取平均。网页摘要显示这一项。
完全覆盖
本题所有金标准类和属性都覆盖的 CQ 占全部 CQ 的比例。

全领域 F1 高、平均 CQ 覆盖低，通常表示词汇基本找对了，但有些词放错了问题，或漏掉了个别问题所需词项。

原报告的 Step 5 — CQ Coverage 同时列出至少一项、逐题平均和完全覆盖。逐题表会列出每题缺失的类和属性；它比单个综合 F1 更适合定位是哪道 CQ 出了问题。

问题：由一组 CQ 生成的本体，是否包含回答它们所需的词项、属性语义、domain/range、公理与可推出的层级？CQ2Onto 不是一项分数，而是按依赖顺序运行的多维评测。

先看执行主干

  1. 01
    类对齐

    从预测和金标准本体抽类，得到一对一类映射与类 F1。输出 class_best_matching.csv。

  2. 02
    属性对齐与属性特征

    分别对齐对象属性、数据属性，得到属性映射和属性 F1；在此基础上检查七种 OWL 属性特征。输出 property_best_matching.csv。

  3. 03
    三元组结构

    复用类与属性映射，比较 rdfs:domain / rdfs:range；分语义诊断、已对齐严格比较和全局比较。

  4. 04
    Atomic TBox 抽取

    把预测本体拆成可比较的原子 TBox 公理。这是中间产物，本身没有一个“Atomic 分数”。

  5. 05
    公理与严格 CQ 覆盖

    用映射比较公理结构并标记 TP / FP / FN / mismatch / skip；再按每个 CQ 关联的金标准公理计算严格覆盖。

  6. 06
    HermiT 闭包与 CQ 补救

    推理金标准和预测本体中的类/属性层级关系，计算层级分数；对可被推理补足的 CQ 公理进行闭包补救分析。

后续结构评测依赖前两步的映射。类或属性映射出错，三元组、公理和层级可能连带变差。排查时应沿 01 → 06 的顺序看，不要先盯最后一个 F1。

词项匹配用到哪些方法

这里的“方法”是评测器在比对两个词项时使用的相似度方法，不是生成本体的 normal、cqbycq、agent 三种方案。三种生成方案最终都只提交一个领域本体，进入相同的评测流程。

Hard match
词项标签规范化后完全相同，候选配对直接记 1.0；大小写等表面差别先被规范化。
Sequence match
比较两个规范化字符串的字符顺序相似程度，适合观察局部改写与顺序差别。
Levenshtein
比较字符串编辑差异，拼写相近时可能给高分；词义相同而拼写不同不一定得分高。
Jaro-Winkler
比较字符串字符与前缀相似程度，对短词项和前缀相近的写法有帮助。
Semantic
用本地 embedding 模型比较文本语义，能提示词义接近的候选，但高余弦相似度不证明结构正确。
Top-N 聚合
硬匹配成功直接采用 1.0；其余候选取最高的 N 个非硬匹配方法分数求平均，低于最终阈值则拒绝。

默认 N=3，类最终阈值 0.6、属性最终阈值 0.7。候选按聚合分数从高到低贪心选择，一个金标准词项和一个预测词项各最多选一次。报告第 2 层的各方法 P/R/F1 是方法独立运行的诊断值，第 3 层的综合配对才交给下游使用。

例如 PlantParts 与 Plant Part 可以因字符串和语义相近被对齐；而 Plant 与 PlantParts 即使字符相似，也会受阈值和一对一竞争约束。是否最终选中，请看 alignment trace 的 selected 与 reason。

01–02 类与属性对齐

输入：预测本体和 CQ 对齐的金标准本体。类层从两边抽取命名类；属性层区分对象属性与数据属性，统计两侧各有多少。这里的对象是本体词汇，不是用户在 Web 中填写的“模型标签”。

处理：第 1 层给出数量，第 2 层让每种相似度方法独立对齐并计算诊断 P/R/F1，第 3 层按 Top-N 聚合候选、一对一选择最终映射。类和属性分别导出 alignment_trace.csv/json 与 *_best_matching.csv；后者是下游三元组、公理、层级评测的输入。

指标：最终匹配的金标准词项算 TP，剩余预测词项算 FP，未匹配金标准词项算 FN，分别得到类和属性的 Precision / Recall / F1。摘要里的“类 F1”“属性 F1”来自最终综合对齐，不是任一单方法的 F1。

怎么读：类 F1 高而三元组 F1 低，说明词汇可能认对但 domain/range 关系有误；类 F1 低时先查 trace 里的候选分数、阈值拒绝和一对一竞争，再解释下游结构分数。对齐成功也不意味着公理正确。

原报告位置：Class-Level Label Matching Report / Property-Level Label Matching Report。先看 Layer 1 数量，再看 Layer 2 单方法结果，最后看 Layer 3 最佳配对与 Overall。原始文件对应 01_class/、02_property/。

02 属性特征

输入：属性对齐表与两边本体中对象属性的 OWL 类型声明。检查七类特征：Functional（函数性）、InverseFunctional（逆函数性）、Transitive（传递性）、Symmetric（对称性）、Asymmetric（非对称性）、Reflexive（自反性）、Irreflexive（非自反性）。

判定：对每个已对齐对象属性对，逐个特征比较：两边都有为 TP；只有预测有为 FP；只有金标准有为 FN。两边都没有该特征时不产生一个“正确的零”，避免大量不存在的特征虚增 TP。两边都没有任何特征的属性对会被跳过。

两个范围：pair-level / AC 只统计已对齐属性对；ontology-level / Global 还会把有特征但完全未对齐的金标准对象属性计为 FN。后者更接近整体覆盖情况，因此两个范围即使都叫 F1，也不能直接当成同一个分数。

解读：例如金标准要求 Transitive，预测写成 Symmetric，Transitive 是 FN、Symmetric 是 FP。脚本还标出 Symmetric/Asymmetric、Reflexive/Irreflexive 的互斥关系，方便发现语义冲突。

原报告位置：Property-Level Label Matching Report 末尾的 All Characteristics — pair-level 与 ontology-level。先核对这两个表的分母，再看各特征的 TP/FP/FN。

03 domain / range 三元组

输入：两边本体的对象/数据属性，以及上游类、属性映射。这里的“三元组”重点是每个属性的 rdfs:domain、rdfs:range 声明；并非统计上传文件里所有 RDF 三元组。

Layer 1 · 统计
分别数出有完整 domain+range、只有 domain、只有 range、两侧均未声明的属性；这层没有结构 F1。
Layer 2 · 语义概览
把属性及其声明渲染成文本，用 embedding 余弦相似度在同一属性类型内做阈值配对，报告候选的 P/R/F1。它衡量“文本语义接近”，不是严格 domain/range 相等。
Layer 3 · 严格 / AC
只看上游已对齐的属性对。对象属性的 domain/range 借助类映射比较；数据属性的 range 比较规范化数据类型。
Layer 4 · 全局
保留严格层的 TP，并把未对齐属性上的多余预测声明计 FP、缺失金标准声明计 FN，从整个本体范围重新计算分数。

单侧判定：两边都没声明为 skip；只在预测中声明为 FP；只在金标准中声明为 FN；两边声明并一致为 TP；两边都有但不一致为 mismatch，同时计入 FP 和 FN。对象/数据属性类型错配会单列诊断，避免误把两种属性的 range 混在一起。

怎么读：Layer 2 高、Layer 3 低，说明文字看似相近但结构没有对上；Layer 3 高、Layer 4 低，说明已对齐的属性结构较好，但还有未对齐属性或声明。

原报告位置：Property-Axiom (Triple) Evaluation Report 的 Layer 1–4。详情可查 03_triple/triple_result.json 和 layer3_pairs.csv/json。

04–05 Atomic TBox 与公理

先抽取，再比较。Atomic TBox 脚本把预测本体拆成结构化的类/属性公理，生成 JSON、TXT、XLSX，作为公理评测输入。它是中间阶段，没有“Atomic F1”；若抽取失败，下游公理和层级阶段无法正常继续。

Layer 1 · 数量
按词项与公理类型统计金标准和预测有多少条。数量接近不代表内容正确。
Layer 2 · 语义候选
把公理表达式转成文本，用 embedding 余弦相似度寻找一对一候选。相似公理可有不同的逻辑结构，因此它仅作诊断；该层若被关闭或计算失败，脚本仍可继续严格和全局结构评测。
Layer 3 · 严格结构
先使用类/属性映射定位主题，再比较公理类型与内部表达式，包括类、属性、数据类型及复合逻辑结构。每个预测公理最多用于匹配一条金标准公理。
Layer 4 · 全局范围
在 Layer 3 结果之上，把未对齐主题上的金标准公理加到 FN，把未对齐主题上的预测公理加到 FP；TP 不变。

Layer 3 状态：TP 是结构匹配；FN 是已对齐主题缺少对应公理；pure FP 是已对齐主题有额外预测公理；mismatch 是同类公理存在但表达式不一致，既是预测侧错误也是金标准侧缺口，所以 FP 和 FN 各加一次；skip 是主题根本没有对齐，在严格层暂不计分，进入全局层后再计入。

例如金标准写 Carnivore ⊑ Animal，预测的对应类却只写了 Carnivore ⊑ Plant：主题虽然能对齐，但上位类不同，应查 mismatch / FN，而不能只看“有一条 SubClassOf”就当作命中。类似地，预测多写的 Declaration 等公理可能进入 FP，因此“类名全对”并不保证公理 F1 高。

原报告位置：Axiom-Level TBox Evaluation Report 的 Layer 1–4。若想知道为何分低，先看 Layer 3 的 TP / Mismatch / FN / Pure FP / Skip 明细，再看 Layer 4 额外纳入了多少未对齐公理。结构化明细在 04_axiom/eval_axioms_result.json、details.csv。

06 HermiT 层级闭包

输入：金标准本体、预测本体以及前面得到的类/属性映射。HermiT 分别计算两边可推出的 SubClassOf、SubPropertyOf 等层级事实；等价类/等价属性可以对应双向包含关系。

比较：先把预测侧层级事实翻译到金标准词汇，再与金标准闭包求交集得到 TP；多余预测事实为 FP，缺失金标准事实为 FN。无法通过对齐表翻译的预测事实也计入 FP。类、属性和合并后的 P/R/F1 分别展示。

断言与推理：报告中的 [asserted] 表示源 OWL 直接声明，[inferred] 表示 HermiT 推出。只要闭包事实一致，预测不必用同样的显式公理写法；但层级 F1 高也不能证明其他公理或每个 CQ 都完整。

原报告位置：HermiT Closure Evaluation Report 的 Closure sizes、Metrics 和类/属性层级详情。先查未翻译预测事实与 FN 列，再回看上游对齐表。原始结果在 05_hierarchy/hierarchy_result.json 与 hierarchy_pairs.csv。

05–06 把结果映射回 CQ

来源：金标准中的每条 TBox 公理带有所支持的 CQ ID。同一公理可能服务多道 CQ。对某题的覆盖率，只用该题关联的公理作分母，不能用整个本体的公理数替代。

严格口径：公理 Layer 3 中得到 TP 的金标准公理计为已覆盖；FN、mismatch、skip 均不算已覆盖。每道题先得出 TP 公理数 / 所需公理数，再汇总：

至少一项覆盖
有至少一条所需公理为 TP 的 CQ 数 / 全部 CQ 数。
平均覆盖
先对每个有关联公理的 CQ 算覆盖比例，再取平均；不要与“至少一项”混读。
完全覆盖
所有所需公理都为 TP 的 CQ 数 / 全部 CQ 数。
逐题明细
列出题目、TP / Total、缺失公理 ID 和状态，帮助定位哪条约束没有实现。

闭包补救口径：层级脚本再看金标准层级公理涉及的包含关系能否由预测本体推导出来。严格已得 TP 的公理不会重复加分；严格未命中但闭包能够证明的相关层级关系可被补救。复合公理有多条必要关系时，需要全部满足才算完整补救；未标注到单一 CQ 的推理链事实只用于层级总体比较。

闭包的“至少一项”和“完全覆盖”同时考虑严格匹配与闭包补救；每题平均率结合严格 TP 与可补救关系。它不等于“把所有未命中的复杂公理都当作正确”。因此严格与闭包两组值都要看，差值才说明推理多挽回了多少。

原报告位置：Axiom-Level TBox Evaluation Report → CQ Coverage (strict)，以及 HermiT Closure Evaluation Report → CQ Coverage (closure-based)。先核对严格逐题缺失公理，再看闭包的 Closure-rescued 和 Missing closure facts。

  2. 读最终映射。Layer 2 单方法分数只供诊断；以 Layer 3 最佳配对表为准，检查名称不同但被判成同一个词项的项，以及应匹配却被阈值拒绝的项。
  3. 拆开看结构口径。Triple 和 Axiom 的 Layer 2 是语义候选，Layer 3 是已对齐项上的严格比较，Layer 4 才纳入未对齐项。不要把三层 F1 当作同一口径的重复结果。
  4. 对照错项列表。看 TP、FN、Pure FP、Mismatch、Skip：FN 指向漏建，Pure FP 指向多建，Mismatch 指向表达式不一致，Skip 指向对齐缺口。报告只在有相应结果时列出某些明细表。
  5. 最后看推理与 CQ。层级表告诉你哪些包含关系可以推出；严格与闭包 CQ 表告诉你这些关系是否对具体问题有帮助。结合 AX ID 追到所需公理。
